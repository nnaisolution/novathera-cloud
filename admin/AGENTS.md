# Folder Structure

This project uses a feature-based architecture. Follow it strictly when adding any new code.

```
app/
  (dashboard)/    ← authenticated dashboard pages (employees, services, locations, bookings, customers, payments)
  (routes)/       ← auth pages (login, register, verify-email)
  layout.tsx
  globals.css

components/
  ui/             ← primitives only: shadcn/ui components
  shared/         ← cross-feature: nav, layouts, form wrappers, error boundaries
  features/
    <feature>/    ← one folder per feature (see below)

lib/
  trpc/           ← tRPC client (connects to nova_thera_nest_app at NEXT_PUBLIC_API_URL)
  auth/           ← better-auth client, RBAC permissions (mirrors the backend's ac/roles)
  hooks/          ← hooks used across multiple features
  utils/          ← shared utility functions

types/
  trpc/           ← generated app-router.d.ts — never edit by hand, regenerated by `pnpm trpc:sync` in the backend
  index.ts        ← app-wide types only
```

A feature folder only includes the subfolders it needs:

```
components/features/<feature>/
  components/     # <Feature>View and children
  hooks/          # use-<feature>.ts, wired to the tRPC client
  schemas/        # Zod validation (forms, mutation input)
  utils/          # feature-only helpers
  types.ts
  index.ts        # exports the public view(s) and hooks
```

## Rules

- **New feature?** Create `components/features/<feature-name>/` with the subfolders it needs. Never dump feature code directly into `components/` root.
- **New page?** Add it under `app/(dashboard)/` or `app/(routes)/`. Pages import only from `components/features/`, no inline logic or business logic in the page file.
- **Reusable primitive?** Goes in `components/ui/`. Zero feature-specific logic.
- **Shared hook or util?** If used by more than one feature, `lib/hooks/` or `lib/utils/`. Otherwise it stays in the feature folder.
- **Cross-feature imports**: don't reach into another feature's internals (e.g. `bookings` importing from `employees/components`). Share via `components/shared/`, `lib/`, or `types/`.
- Use the `@/` alias for all imports.

# Data access: tRPC client only

This app has **no REST/axios API layer**. All server data goes through the tRPC client in `lib/trpc/client.ts`, typed against `types/trpc/app-router.d.ts` (generated from the NestJS backend — see root `CLAUDE.md`).

- Never call `fetch` directly for domain data from a component.
- Wrap each call in a feature hook (`use-<feature>.ts`) using `useTRPC()` + TanStack Query — components call the hook, not the client directly.
- If a type you need is missing or stale, that means the backend needs `pnpm trpc:sync` re-run — do not hand-edit `types/trpc/app-router.d.ts`.

```tsx
// BAD — fetch in a view
export function EmployeesView() {
  const [data, setData] = useState(null);
  useEffect(() => { fetch("/api/employees").then(...) }, []);
}

// GOOD — hook wraps the tRPC client
export function useEmployees() {
  const trpc = useTRPC();
  return useQuery(trpc.employees.list.queryOptions());
}
```

# UI: shadcn + Lucide only

- Use the **shadcn MCP** before writing UI — don't guess component APIs or invent primitives.
- Only compose screens from `@/components/ui/*` (installed shadcn/ui). No MUI, Chakra, bare Radix outside `components/ui`, or hand-rolled substitutes for things shadcn already provides.
- Icons come **only** from `lucide-react`. Never emoji-as-icon, Unicode symbols, `react-icons`, `@heroicons/*`, or Font Awesome.
- **No emojis** anywhere in UI copy — labels, buttons, placeholders, empty states, toasts.

<!-- END:ui-rules -->

# Working style

- State assumptions before implementing; if a request has multiple reasonable interpretations, say so instead of silently picking one.
- Write the minimum code that solves the problem — no speculative flexibility or config nobody asked for.
- When editing existing code, touch only what the task requires. Don't reformat or "improve" adjacent code.
- `lib/auth/permissions.ts` is **generated** — `pnpm trpc:sync` in the backend overwrites it with the backend's `src/authentication/permissions.ts`. Never edit it here; the change belongs in the backend, followed by a re-sync. Same for `types/trpc/app-router.d.ts`.
